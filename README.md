# Matema — портал тренажёров по польской программе

Веб-тренажёры для подготовки к контрольным и самостоятельным. Сейчас их два:

| Тренажёр | Охват | Откуда берутся задачи |
|---|---|---|
| Математика | szkoła podstawowa 5–8, liceum 1–4, poziom podstawowy / rozszerzony | генерирует ИИ (Google Gemini, бесплатный тариф), с догенерацией из пула |
| Биология | liceum klasa 3, zakres rozszerzony — анатомия и физиология человека | рендерятся офлайн из шаблонов, **без обращения к ИИ** |

Интерфейс на RU / EN / PL. Задачи по математике — на всех трёх языках, по биологии — на польском
и русском (`TrainerWeb.contentLangs`; при английском интерфейсе стартовая страница спрашивает, на
каком языке провести сессию).

## Структура

```
apps/api                Fastify API: /api/trainers/:id/{topics,generate,feedback}, /api/health
apps/web                портал: шапка, каталог, ленивая загрузка тренажёров (/t/:id)
packages/core           общие zod-схемы и типы (Task, Topic, TaskSlot…)
packages/ai             LLMClient: Gemini, mock, общая очередь запросов
packages/task-pool      пул проверенных задач (SQLite, с trainer_id и сквозными тегами)
packages/trainer-sdk    контракт тренажёра (TrainerServer / TrainerWeb), общий пайплайн генерации
                          и движок офлайн-шаблонов (subpath ./templates)
packages/ui             общие React-компоненты
packages/trainers/math  тренажёр математики:
                          src/         темы и проверка ответов (общее для web и api)
                          src/server/  промпты, валидация задач, mock-ответы, mathTrainer
                          src/web/     экраны, store, переводы, mathTrainerWeb
packages/trainers/bio   тренажёр биологии (та же структура), плюс:
                          src/server/templates/data/   таблицы контента — основной объём работы
                          src/server/templates/topics/ шаблоны задач по главам
                          src/curriculum/lo.ts         главы и параграфы учебника
                          scripts/genCoverage.ts       какие параграфы наполнены (для веба)
                          scripts/renderTemplates.ts   офлайн-рендер и синхронизация пула
```

## Запуск

```bash
npm install
cp .env.example .env        # вписать GEMINI_API_KEY (https://aistudio.google.com/apikey)
npm run dev                 # сервер :8787 + фронт :5173 (прокси /api)
```

Без ключа работает `LLM_PROVIDER=mock`: простые арифметические задачи, всё остальное как с настоящим ИИ.

Продакшен: `npm run build && npm start`. Сервер сам отдаёт собранный фронт из `apps/web/dist`.

## Откуда берутся задачи

Два пути, и тренажёр выбирает свой через `TrainerServer.usesLLM`.

### Офлайн-шаблоны (биология, и пилотные темы математики)

Задача пишется один раз как шаблон над таблицей контента, а рендерер разворачивает её в десятки
конкретных задач: один шаблон плюс таблица на 24 строки даёт 24 задачи на каждом языке. Основной
труд уходит в `templates/data/*.ts`, а не в код.

```bash
npm run render:templates -w @portal/trainer-bio -- --db=./data/bio.db   # посмотреть контент локально
npm run gen:coverage -w @portal/trainer-bio                            # после любой правки контента
```

Каждая отрендеренная задача проходит **тот же** верификатор, что и ответ ИИ. У числовых задач
расчёт записан дважды — формулой mathjs и на TypeScript — и задача отбраковывается, если два
результата разошлись.

**Деплою ручной шаг не нужен.** На первой сессии каждый инстанс сервера сверяет пул с шаблонами
(`TrainerServer.ensureContent`): id задачи биологии — хэш её содержимого, поэтому «другой id» значит
«другая задача». Новые задачи дописываются, те, которых шаблоны больше не дают, удаляются. Так до
прода сами доезжают исправленный текст, задача, перенесённая в другой параграф, и новый контент.
Скрипт делает ту же синхронизацию и нужен только чтобы посмотреть результат заранее.

Каждая задача лежит в параграфе учебника. Строки таблицы, относящиеся к разным параграфам, несут
своё поле `paragraph` (`P.motion.joints`), дистракторы же берутся из всей таблицы. Веб не умеет
рендерить шаблоны, поэтому число задач по параграфам лежит в сгенерированном
`curriculum/coverage.generated.ts`; тест падает, если файл отстал от контента.

### Генерация через ИИ (математика)

1. Задачи распределяются по выбранным темам. Сложность: примерно 30% лёгких, 50% средних, 20% трудных.
   Часть задач (`POOL_REUSE_RATIO`, по умолчанию половина) берётся из пула уже проверенных задач, которые этот ученик ещё не видел.
   Остальные генерируются пачками до 5 задач: темы внутри пачки смешиваются, поэтому 10 задач — это 2 запроса к ИИ при любом числе тем.
   Все запросы к ИИ проходят через общую очередь сервера (`LLM_MAX_CONCURRENT`, `LLM_RPM`).
2. Gemini возвращает JSON по схеме. Для числовых ответов модель также присылает `verifyExpression`: выражение, которое вычисляет ответ из условия.
3. Сервер проверяет каждую задачу (`packages/trainers/math/src/server/verifyTask.ts`):
   - схема данных;
   - `verifyExpression` должен совпасть с ответом (через mathjs);
   - в задачах с выбором ровно один верный вариант.

   Отбракованные задачи догенерируются. Прошедшие проверку сохраняются в пул (SQLite).
   Если ИИ недоступен или квота исчерпана, недостающие задачи добираются из пула.
   Модели перебираются по порядку (`GEMINI_MODEL`, затем `GEMINI_FALLBACK_MODEL`). Модель, получившая 429, пропускается
   на время из ответа Google, а при исчерпании суточной квоты — на час. Состояние видно в `GET /api/health`.
4. Ответ ученика проверяется на клиенте (`packages/trainers/math/src/answer.ts`). Эквивалентными считаются `0,5`, `1/2` и `.5`; `2√3` и `2*sqrt(3)`. Корни проверяются без учёта порядка (`2; -3`), выражения — подстановкой значений.

## Сквозные темы

Гомеостаз не принадлежит одному działу: он в терморегуляции, регуляции дыхания, ADH, вегетативной
регуляции и обмене глюкозы. Поэтому у задач есть плоские метки (`Task.tags`), а не второй уровень
иерархии тем. Стартовая страница биологии умеет набирать сессию «по параграфам» или «по теме»; каталог
тем — `packages/trainers/bio/src/curriculum/tags.ts`. В какие параграфы раскрывается тема, берётся из
сгенерированного покрытия, то есть из того, что реально проставляют шаблоны.

## Переменные окружения

| Переменная | По умолчанию | |
|---|---|---|
| `LLM_PROVIDER` | `gemini`, если есть ключ, иначе `mock` | |
| `GEMINI_API_KEY` | — | ключ Google AI Studio |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | модели и лимиты бесплатного тарифа меняются, сверяйтесь с AI Studio |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.1-flash-lite,gemini-3.6-flash` | запасные модели через запятую; у каждой своя квота |
| `LLM_MAX_CONCURRENT` | `4` | сколько запросов к ИИ одновременно на весь сервер |
| `LLM_RPM` | `15` (mock: без лимита) | запросов к ИИ в минуту на весь сервер |
| `LLM_QUEUE_WAIT_MS` | `45000` | сколько запрос может ждать в очереди, потом ошибка «слишком много запросов» |
| `TASK_DB_PATH` | `apps/api/data/tasks.db` | файл пула задач |
| `POOL_REUSE_RATIO` | `0.5` | доля задач из пула в каждой тренировке; тренажёр может переопределить (у биологии всегда 1) |
| `PORT` | `8787` | |
| `CORS_ORIGIN` | любой | список через запятую |

## Тесты

```bash
npm test          # vitest: проверка ответов, валидаторы задач, пул, рендер шаблонов
npm run typecheck
npm run e2e       # playwright; перед стартом сервера сам рендерит пул биологии
```

Самый ценный тест в биологии — `src/server/templates/render.test.ts`: он рендерит каждый шаблон на
обоих языках и разом ловит недостающие переводы, совпадающие дистракторы, битые ссылки в таблицах
и расхождение формулы с ответом.

## Справочник тем

`packages/trainers/math/src/curriculum/{sp,lo}.ts` — это черновая раскладка по классам на основе популярных учебников.
Сверьте её с podstawa programowa и учебником конкретной школы. Подтемы записаны по-польски, они идут в промпт.

`packages/trainers/bio/src/curriculum/lo.ts` — оглавление «Biologia na czasie 3 ZR» (Nowa Era):
11 глав и 54 параграфа со страницами. Тема тренажёра — параграф, глава только группирует их в
выборе. Id параграфа — слаг (`bio.lo3.motion.skeleton`), а не номер: другое издание может
перенумеровать книгу, а история и прогресс привязаны к id. Параграфы без задач видны, но выбрать их
нельзя. Все темы уровня `R`: на расширенном уровне весь год занимает анатомия и физиология
человека, поэтому стартовая страница не предлагает выбор класса и уровня, а жёстко передаёт `lo3` / `R`.

## Как добавить тренажёр

1. Создать пакет `packages/trainers/<id>` (по образцу `math`) с тремя входами:
   - `.` — темы и проверка ответа (используются и в браузере, и на сервере);
   - `./server` — объект `TrainerServer`: `topicsFor`, `generateTaskBatch` (промпт + JSON-схема + mock-ответ), `verifyTask`, `checkAnswer`, `generateFeedback`;
   - `./web` — объект `TrainerWeb`: название, описание, иконка, переводы (namespace = id) и `load: () => import("./App.tsx")`.
2. Зарегистрировать тренажёр в `apps/api/src/trainers.ts` и `apps/web/src/trainers.ts`.
3. Пайплайн генерации (пул, пачки, очередь, догенерация) общий — в `@portal/trainer-sdk/server`, его писать не нужно.
4. Если контент пишется руками, а не генерируется: `usesLLM: false`, `reuseRatio: 1`, `ensureContent`
   (синхронизация пула с шаблонами), движок шаблонов из `@portal/trainer-sdk/templates` и свой скрипт
   рендера по образцу биологии. У офлайн-тренажёра слоты темы, в которой кончились задачи, добираются
   из других выбранных тем. Движок берёт верификатор параметром, так что предметные проверки
   остаются в тренажёре.

После правки `apps/api/src/trainers.ts` нужно пересобрать и закоммитить `api/index.js`
(`node scripts/build-vercel-function.mjs`): Vercel проверяет бандл до того, как выполнит `buildCommand`.

Приложение тренажёра получает `lang` и `setLanguageLocked` от портала и грузится отдельным чанком.
