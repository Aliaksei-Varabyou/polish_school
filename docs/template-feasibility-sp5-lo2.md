# Оценка шаблонизируемости: SP5 и LO2 (poziom podstawowy)

Дата: 15.09.2026.
Цель документа: оценить (для планирования трудозатрат, не как спецификацию) насколько тема/подтема
куррикулума SP5 и LO2-P поддаётся переводу в `TaskTemplate` (см. черновой дизайн в разделе
«План: шаблонная генерация задач» — `params` + `constraint` + `derive` + `correctAnswer`,
шаблон без `params` = одна ручная задача).

**Источник списка тем.** За основу взят не текущий код `sp.ts`/`lo.ts`, а **исправленный** список
тем/подтем из `docs/curriculum-review.md` (раздел 5, чеклист правок). Там, где ревизия предписывает
удалить, переименовать или перенести подтему/тему — здесь используется исправленная версия. Ссылки
вида «чеклист: …» — это прямые пункты из раздела 5 `curriculum-review.md`.

Все числа в этом документе — **оценки** автора документа (не измерены на реальном рендерере,
шаблонов пока не существует). Явных фактов из внешних источников (кроме самого списка тем) здесь нет.

Условные обозначения вердикта:
- **Л** (легко) — чистая вычислительная задача, параметризуется почти без усилий.
- **С** (осторожно) — параметризуется, но текстовая формулировка (обычно word problem) требует
  внимания к согласованию числительных RU/PL или к «красивости» результата.
- **Н** (не параметризуется) — нужен маленький вручную написанный набор без подстановок (шаблон
  с пустым `params`), потому что задача требует разного *хода рассуждения* в каждом экземпляре, а
  не просто других чисел (доказательства, построения, распознавание фигур по картинке).

### `sp5.natural` — Działania na liczbach naturalnych
Подтемы по чеклисту: «kwadraty i sześciany liczb» (не «potęgi o wykładniku naturalnym» — чеклист:
«заменить „potęgi o wykładniku naturalnym“ на „kwadraty i sześciany liczb“»), «kolejność
wykonywania działań», «zadania tekstowe», плюс добавленные «system rzymski (do 3000)», «szacowanie
wyników», «dzielenie z resztą: a = b·q + r».

- **Вердикт:** порядок действий, квадраты/кубы, деление с остатком — Л (чистая арифметика).
  Римские цифры — Л, но это скорее «конвертер», чем расчёт (параметр — число 1–3000, ответ строка).
  Word problems (закупки, расстояния) — С: нужно согласование существительных («5 яблок» / «2
  яблока» / «1 яблоко»).
- **Оценка шаблонов:** 10–14. Разные *формы* задачи: порядок действий с 1–2 скобками (2–3 формы по
  сложности), квадрат/куб числа (1), смешанное выражение со степенью (1), деление с остатком (1–2:
  «найти частное и остаток» / «restore дивиденд по частному и остатку»), римские цифры (1: туда,
  1: обратно), округление/прикидка результата (1–2), word problem на 2–3 действия (2–3 сюжета).
- **Типичные параметры:** для порядка действий — 4 целых a,b,c,d (1–20) и фиксированный шаблон
  выражения вида `a + b·c − d`; для деления с остатком — делимое (2–3-значное), делитель (2–9,
  ≠делитель делимого без остатка, иначе скучный случай). Реалистично **~20–30 комбинаций/шаблон**
  для чистой арифметики (большой пул целых чисел, почти все дают «красивый» ответ); для word
  problems — **~10–15 комбинаций/шаблон**, потому что сюжет и типы существительных ограничивают
  разумный диапазон количеств (не «0,3 яблока»).
- **Разброс сложности:** хорошо покрывает 1–3: простое вычисление = 1, выражение с несколькими
  скобками/степенью = 2, многошаговый word problem = 3.
- **Непараметризуемое:** нет полноценно нешаблонизируемых подтем; при желании можно добавить 3–5
  ручных концептуальных вопросов («почему важен порядок действий») — не обязательно.

### `sp5.divisibility` — Własności liczb naturalnych
Подтемы: «cechy podzielności», «liczby pierwsze i złożone», «rozkład na czynniki pierwsze» (по
чеклисту — числа ≤3-значные, не более одного множителя >10), «NWD i NWW» (числа ≤3-значные).

- **Вердикт:** Л. Чистая теория чисел, диаграмм/картинок не требует.
- **Оценка шаблонов:** 15–20. Признаки делимости — по одному шаблону на правило или группу правил
  (2,5,10 / 3,9 / 4,6) — 3–4 формы; простое/составное число — классификация (1–2, включая «найди
  все простые в диапазоне»); разложение на множители — 3–4 формы по сложности (2 множителя / 3+
  множителей / с ограничением «не больше одного множителя >10»); НОД/НОК — вычисление (2) плюс
  word problems «когда события совпадут» для НОК и «максимальный размер группы» для НОД (2–3).
- **Типичные параметры:** N (3-значное число) для признаков и разложения; пара (a,b) для НОД/НОК,
  оба ≤200–500, специально подобранные так, чтобы НОД был >1 (иначе задача тривиальна) — это
  типичный `constraint`. Реалистично **~25–40 комбинаций/шаблон** для признаков делимости и
  разложения (большой пул целых чисел без специальных требований к «красоте» ответа), **~10–15
  комбинаций/шаблон** для word problems НОД/НОК (нужны правдоподобные сюжетные числа).
- **Разброс сложности:** 1–3 хорошо покрывается (признак делимости = 1, разложение на множители с
  ограничением = 2, word problem на НОК = 3).
- **Непараметризуемое:** нет.

### `sp5.fractions` — Ułamki zwykłe
Подтемы (без изменений в чеклисте, «OK»): skracanie i rozszerzanie, porównywanie, liczby mieszane,
dodawanie i odejmowanie, mnożenie i dzielenie; ограничение V.1 — знаменатели 1–2-значные.

- **Вердикт:** Л для чистых вычислений, С для word problems («доля от количества предметов»).
- **Оценка шаблонов:** 14–18. Сокращение/расширение (2), сравнение (одинаковый/разный знаменатель —
  2), перевод смешанное↔неправильная дробь (2), сложение/вычитание (одинаковый знаменатель /
  разный, включая НОК знаменателей — 2–3), умножение/деление (2–3), word problem «какая часть
  количества» (2–3, например «часть пути», «часть класса»).
- **Типичные параметры:** числитель/знаменатель с ограничением «знаменатель 1–2-значный» и
  `constraint`, чтобы результат сокращался до простой дроби (не оставался «уродливым»
  трёхзначным). Пример: a/b + c/d, где НОК(b,d) ≤ 100. Реалистично **~15–25 комбинаций/шаблон** —
  диапазон уже ограничен требованием «красивого» результата (простая несократимая дробь или целое
  число), т.е. заметная доля случайных пар (числитель, знаменатель) отбраковывается.
- **Разброс сложности:** хорошо 1–3 (сокращение = 1, разный знаменатель = 2, word problem = 3).
- **Непараметризуемое:** нет.

### `sp5.decimals` — Ułamki dziesiętne
Подтемы: zamiana ułamków zwykłych na dziesiętne, porównywanie, działania, jednostki długości i
masy; ограничения 2024 г. по чеклисту — письменные действия только если сумма ненулевых цифр
слагаемых ≤6, округление — не дальше сотых, в практическом контексте.

- **Вердикт:** Л для вычислений (важно правильно закодировать ограничение «≤6 значащих цифр» как
  `constraint`, иначе сгенерируются нереалистично длинные примеры), С для word problems с деньгами/
  измерениями.
- **Оценка шаблонов:** 12–16. Перевод дробь→десятичная и обратно (2), сравнение (1–2), сложение/
  вычитание с учётом лимита цифр (2), умножение/деление на целое и на десятичную дробь (2–3),
  округление до заданного разряда в практическом контексте (1–2), перевод единиц длины/массы
  (2), word problem с покупками/измерениями (2–3).
- **Типичные параметры:** два десятичных числа a,b с `constraint` «суммарно ≤6 ненулевых цифр»;
  разряд округления (десятые/сотые); коэффициент перевода единиц (мм↔см↔м↔км, г↔кг). Реалистично
  **~15–25 комбинаций/шаблон** для операций (ограничение по цифрам заметно сужает пул валидных
  пар по сравнению с «любые два десятичных числа»), **~10–15** для word problems.
- **Разброс сложности:** 1–3 хорошо (сравнение = 1, действие с лимитом цифр = 2, word problem с
  переводом единиц = 3).
- **Непараметризуемое:** нет полноценно; можно добавить 3–5 ручных концептуальных задач про то,
  зачем округляют «в практическом контексте», но это не обязательно.

### `sp5.integers` — Liczby całkowite
Чеклист отмечает тему как «неясно (класс)», но с уточнением: в базе IV–VI это только ось, модуль,
сравнение и «proste rachunki pamięciowe» — то есть тема намеренно **мелкая**, полноценные действия
переезжают в `sp6.rational`.

- **Вердикт:** С — параметризуется, но диапазон нужно держать нарочно узким (устный счёт), иначе
  тема перестанет соответствовать программе SP5.
- **Оценка шаблонов:** 7–10 (меньше, чем у других тем — сама тема неглубокая). Отметить число на
  оси (1–2), сравнение целых чисел (1–2), простое сложение/вычитание в уме (2–3, диапазон -20..20),
  word problem температура/высота (2–3).
- **Типичные параметры:** целые числа в диапазоне -20..20 (устный счёт); для word problems —
  «температура утром/вечером», «этаж/высота». Реалистично **~15–20 комбинаций/шаблон** — диапазон
  и так узкий по программе, расширять его до «красивости» смысла не имеет.
- **Разброс сложности:** смещён к 1–2, сложность 3 получить сложно без выхода за пределы программы
  SP5 (это по сути ограничение самой темы, не шаблонов).
- **Непараметризуемое:** нет.

### `sp5.angles` — Proste, odcinki i kąty
Подтемы без изменений (чеклист: «OK»): rodzaje kątów, kąty przyległe i wierzchołkowe, proste
prostopadłe i równoległe.

- **Вердикт:** С. Вычислительная часть (найти неизвестный угол) параметризуется легко; но многие
  реальные задачи по этой теме опираются на **картинку** (два угла на чертеже, отметить какие
  прямые перпендикулярны) — если тренажёр только текстовый/числовой, такие вопросы придётся
  переформулировать в чисто текстовые («угол A и угол B — смежные, угол A = 65°, найдите угол B»)
  без чертежа. Это не делает тему нешаблонизируемой, но ограничивает естественность формулировок
  (см. раздел рисков — зависимость от рендеринга диаграмм).
- **Оценка шаблонов:** 8–12. Классификация угла по величине (1), смежные углы (1–2), вертикальные
  углы (1), сумма углов вокруг точки/на прямой (1–2), определение перпендикулярности/параллельности
  по данным углам (2–3, текстовое описание вместо чертежа).
- **Типичные параметры:** величина угла (кратна 5° или 10°, диапазон 5–175°), пары связанных углов.
  Реалистично **~10–20 комбинаций/шаблон** — пул «красивых» градусов (кратных 5) ограничен, плюс
  нужно исключать вырожденные случаи (0°, 180°).
- **Разброс сложности:** тема скорее 1–2 по своей сути (короткие вычисления); сложность 3
  достижима только через многошаговые задачи (несколько связанных углов).
- **Непараметризуемое:** нет отдельной подтемы, требующей ручного набора, но есть риск рендеринга
  диаграмм (см. раздел рисков).

### `sp5.polygons` — Trójkąty i czworokąty
По чеклисту добавлены подтемы: «konstrukcja trójkąta o danych bokach, nierówność trójkąta» (IX.2) и
«oś symetrii figury» (IX.5), к уже имеющимся «suma kątów w trójkącie», «rodzaje trójkątów»,
«własności czworokątów», «obwody wielokątów».

- **Вердикт:** С/Н. Сумма углов треугольника, классификация по сторонам/углам, периметр — Л/С
  (чистые вычисления). Неравенство треугольника (проверить, существует ли треугольник со сторонами
  a,b,c) — параметризуется как задача да/нет с числовым ответом. Но **построение треугольника
  циркулем и линейкой** и «определить число осей симметрии фигуры» — это не числовые вычисления, а
  распознавание/построение по конечному каталогу фигур (равносторонний/равнобедренный треугольник,
  квадрат, прямоугольник, ромб, воздушный змей, правильный пятиугольник/шестиугольник) — реально
  это перечисление, а не диапазон параметров, то есть фактически Н.
- **Оценка шаблонов:** 12–16 для параметризуемой части (сумма углов — 2–3 формы, классификация
  треугольника — 2, свойства четырёхугольников по типу — 3–4 формы на конечный список типов,
  периметр многоугольника — 2–3, неравенство треугольника — 1–2).
- **Типичные параметры:** два известных угла треугольника (третий находится по сумме = 180°),
  стороны треугольника a,b,c (целые 2–30, для неравенства — специально подобранные валидные и
  невалидные тройки), тип четырёхугольника (из конечного списка) как «choice»-параметр, а не
  числовой диапазон. Реалистично **~15–25 комбинаций/шаблон** для числовых форм; для
  «choice»-параметра по типу фигуры число подстановок по сути равно размеру каталога (~6–8), это
  ближе к перечислению, чем к диапазону.
- **Разброс сложности:** 1–3 неплохо покрывается через числовые шаблоны; распознавание фигур обычно
  сложность 1–2.
- **Непараметризуемое:** построение треугольника (реальное циркуль-линейка описание шагов) и подсчёт
  осей симметрии по картинке фигуры — оценка **8–12 ручных задач** (фиксированный каталог фигур,
  каждая требует либо картинки, либо словесного описания уже готового построения — не подстановки
  чисел).

### `sp5.area` — Pola wielokątów
Подтемы без изменений (чеклист: «OK», с нюансом про единицы измерения — XI.4 «без перевода единиц
в процессе вычисления», при этом XI.3 допускает данные, требующие перевода единиц): pole
prostokąta i kwadratu, pole równoległoboku i rombu, pole trójkąta, pole trapezu, jednostki pola.

- **Вердикт:** Л. Чистая вычислительная тема (формулы площади), диаграмм по сути не требует —
  достаточно текстового описания размеров фигуры.
- **Оценка шаблонов:** 12–15. Площадь прямоугольника/квадрата (2), площадь параллелограмма/ромба
  (2), площадь треугольника (2), площадь трапеции (2), задача с переводом единиц площади до/после
  вычисления (2), word problem (площадь участка/комнаты) (2–3).
- **Типичные параметры:** основание/высота (целые 2–50, подобраны так, чтобы площадь была целым
  числом или простой десятичной дробью — например `constraint`: `(a*h) % 2 === 0` для треугольника
  с делением на 2), коэффициент перевода единиц площади (см²↔дм²↔м²). Реалистично **~20–30
  комбинаций/шаблон** для формул площади (большой пул валидных целых пар), **~10–15** для задач с
  переводом единиц (нужно следить, чтобы числа не выглядели искусственно).
- **Разброс сложности:** 1–3 хорошо (площадь прямоугольника = 1, площадь трапеции = 2, word problem
  с переводом единиц = 3).
- **Непараметризуемое:** нет.

### `sp5.cuboids` — Prostopadłościany i sześciany
Подтемы без изменений: siatki brył, pole powierzchni, objętość, jednostki objętości.

- **Вердикт:** Л для площади поверхности/объёма (чистые вычисления по формулам); Н для «сеток
  многогранников» — это по сути «дан набор картинок с развёртками, укажите, какая из них
  соответствует данному многограннику», что требует готовых изображений, а не подстановки чисел.
- **Оценка шаблонов:** 9–12 для параметризуемой части: объём прямоугольного параллелепипеда/куба
  (2), площадь поверхности (2), перевод единиц объёма (2), word problem (наполнение
  бассейна/коробки) (2–3).
- **Типичные параметры:** длина/ширина/высота (целые 2–20, при кубе — одна переменная), коэффициент
  перевода объёма (см³↔дм³↔л↔м³). Реалистично **~20–30 комбинаций/шаблон** для формул объёма/
  площади поверхности (большой пул целых троек), **~10–15** для word problems с переводом единиц.
- **Разброс сложности:** 1–3 (объём куба = 1, площадь поверхности параллелепипеда = 2, word problem
  с переводом единиц = 3).
- **Непараметризуемое:** распознавание/выбор сетки многогранника — оценка **6–10 ручных задач**
  (нужен фиксированный набор готовых изображений разверрток; без картинок эта подтема вообще не
  реализуема как отдельный вопрос).

## LO2 (poziom podstawowy)

Из `lo.ts` темы уровня `"P"` в классе `lo2` — это `lo2.transform`, `lo2.quadratic`, `lo2.quadEq`,
`lo2.trigAcute` и (ошибочно помеченная P) `lo2.quadrilaterals`. По чеклисту `curriculum-review.md`
раздел 5, блок «LO2»:
- `lo2.transform`: **удалить** — сдвиги графика переносятся в `lo1.functions` (P), симметрии
  относительно осей — в новую `lo1.transformR` (R). Значит, в скорректированном списке LO2-P этой
  темы нет.
- `lo2.quadrilaterals`: **заменить** на новую тему `lo2.circles` (P) — «Planimetria – okręgi i
  wielokąty» (углы вписанные/центральные, вписанная/описанная окружность треугольника, длина
  дуги/площадь сектора, правильные многоугольники).
- `lo2.trigAcute`: **расширить** до новой темы `lo2.trigTriangles` (P) — тригонометрия углов
  0°–180°, площадь треугольника ½ab·sin γ, теорema косинусов, площади четырёхугольников через
  тригонометрию.
- Добавлены две новые темы уровня P: `lo2.polynomials` (P) и `lo2.rational` (P) — часть
  материала, который в текущем `lo.ts` ошибочно помечен как R (`lo2.polynomialsR`,
  `lo2.rationalR`) или отнесён к `lo3`, а по действующей базе 2024 г. на P во 2 классе.

Итог: скорректированный список LO2-P — **6 тем**: `lo2.quadratic`, `lo2.quadEq`,
`lo2.polynomials`, `lo2.rational`, `lo2.circles`, `lo2.trigTriangles`.

### `lo2.quadratic` — Funkcja kwadratowa
Подтемы (чеклист «OK», добавлено «zadania optymalizacyjne z funkcją kwadratową», P XIII): postać
ogólna/kanoniczna/iloczynowa, wierzchołek paraboli, najmniejsza/największa wartość w przedziale.

- **Вердикт:** Л для алгебраической части (перевод форм, вершина, экстремум на отрезке,
  оптимизационные word problems), Н для «прочитать свойства функции по графику» — это отдельный
  тип задания школьных сборников, но он предполагает готовый рисунок параболы, а не подстановку
  чисел в текст.
- **Оценка шаблонов:** 10–14. Перевод общий вид → канонический (1), канонический → общий (1),
  вершина по a,b,c (1), нахождение нулей/разложение на множители (1), наим./наиб. значение на
  отрезке [p,q] — это реально **2–3 разных формы**, потому что вершина может лежать внутри
  отрезка или вне его (граничные случаи требуют разного хода решения, не только других чисел),
  оптимизационные word problems (площадь, прибыль) — 3–4 разных сюжета.
- **Типичные параметры:** a,b,c — целые, a≠0, с `constraint` на дискриминант (обычно нужен полный
  квадрат для «красивых» корней/вершины); границы отрезка p<q — целые, отдельно нужен `constraint`
  «вершина внутри/вне [p,q]» в зависимости от формы шаблона. Реалистично **~15–25
  комбинаций/шаблон** — заметная часть троек (a,b,c) отбраковывается требованием целого/красивого
  дискриминанта, это заметно меньше, чем для чистой арифметики.
- **Разброс сложности:** хорошо 1–3: перевод форм = 1–2, экстремум на отрезке с вершиной вне
  отрезка = 2–3, word problem оптимизации = 3.
- **Непараметризуемое:** «прочитать свойства по графику» — оценка **8–12 ручных/полуфиксированных
  задач**, зависит от того, появится ли в тренажёре механизм рисования параболы; если нет — эти
  задачи откладываются, а не превращаются в шаблоны.

### `lo2.quadEq` — Równania i nierówności kwadratowe
Подтемы без изменений (чеклист «OK»): wyróżnik i pierwiastki, nierówności kwadratowe, zadania
tekstowe.

- **Вердикт:** Л. Классическая алгебраическая тема, случаи Δ>0/Δ=0/Δ<0 — естественная лестница
  сложности, не искусственная.
- **Оценка шаблонов:** 9–12. Решение уравнения при Δ>0 (1), Δ=0 (1), Δ<0/нет корней (1),
  квадратное неравенство (2–3 формы: знак старшего коэффициента, знак Δ), word problem, сводящийся
  к квадратному уравнению (3–4 сюжета: площадь, движение, произведение последовательных чисел).
- **Типичные параметры:** a,b,c с `constraint` на нужный знак/значение дискриминанта (обычно проще
  задавать через `derive`: выбрать желаемые корни x₁,x₂ и вычислить b,c из них — так дискриминант
  гарантированно «красивый»). Реалистично **~15–25 комбинаций/шаблон** — при подходе «сначала
  выбрать корни, потом вычислить коэффициенты» практически все комбинации валидны, что выгодно
  отличает эту тему от «перебора троек a,b,c».
- **Разброс сложности:** естественно 1→2→3 по мере усложнения случая Δ.
- **Непараметризуемое:** нет.

### `lo2.polynomials` — Wielomiany (новая тема, P)
Подтемы по чеклисту: stopień i współczynniki, dodawanie/odejmowanie/mnożenie wielomianów,
wyłączanie jednomianu przed nawias, równania wielomianowe w postaci iloczynowej (II.2–3, III.5).

- **Вердикт:** Л. Символьная алгебра без геометрии и без word problems — из всех тем LO2 это,
  вероятно, самая простая для парсинга/проверки на этапе прототипа (нет требования к «красивым»
  числам, коэффициенты валидны почти всегда).
- **Оценка шаблонов:** 7–10. Определить степень/коэффициенты (1), сложение/вычитание многочленов
  (1–2), умножение на одночлен и умножение двучлена на двучлен (2, по чеклисту SP7 общее умножение
  многочленов — вне базы, но в LO2 P оно уже разрешено), вынесение одночлена за скобки (1–2),
  решение уравнения W(x)=0, заданного в разложенном виде (2).
- **Типичные параметры:** коэффициенты многочленов — целые -9..9, степень 2–3. Реалистично
  **~20–30 комбинаций/шаблон** — почти нет ограничений «красивости», кроме исключения нулевого
  старшего коэффициента.
- **Разброс сложности:** 1 — базовые действия, 2 — вынесение множителя, 3 — уравнение в разложенном
  виде с несколькими корнями.
- **Непараметризуемое:** нет.
- **Замечание к `verify`:** здесь численная перепроверка (`verifyExpression`-подобная) не так
  тривиальна, как в арифметике — нужно символьное сравнение многочленов (раскрыть скобки, привести
  подобные, сравнить с ожидаемым через mathjs `simplify`/`expand`), а не просто сравнение чисел.
  См. раздел рисков.

### `lo2.rational` — Funkcja f(x)=a/x i wyrażenia wymierne (новая тема, P)
Подтемы по чеклисту: wykres i własności f(x)=a/x, wielkości odwrotnie proporcjonalne, mnożenie i
dzielenie wyrażeń wymiernych (V.13, II.4).

- **Вердикт:** Л для свойств функции и умножения/деления дробно-рациональных выражений; С для
  word problems «обратная пропорциональность» (рабочие и дни, скорость и время) — классический
  случай, где существительные меняют форму по числу («1 рабочий» / «3 рабочих» / «5 рабочих»).
- **Оценка шаблонов:** 7–10. Свойства f(x)=a/x при данном a (область определения, четверть,
  монотонность на ветви) (2), word problem «обратная пропорциональность» (3–4 разных сюжета),
  умножение/деление рациональных выражений (2).
- **Типичные параметры:** a — ненулевое целое (малое, |a|≤20); для word problems — количество
  «исполнителей» и «время» как целые в разумном диапазоне (2–20), связанные `constraint`
  «произведение постоянно» (k = a·b). Реалистично **~15–20 комбинаций/шаблон**: для чисто
  символьных заданий больше, для word problems меньше (нужны правдоподобные целочисленные пары
  «исполнители×дни»).
- **Разброс сложности:** свойства функции — 1–2, word problem — 2–3.
- **Непараметризуемое:** нет, но см. риск согласования числительных.

### `lo2.circles` — Planimetria – okręgi i wielokąty (новая тема, заменяет `lo2.quadrilaterals`)
Подтемы по чеклисту: kąty wpisane i środkowe (VIII.5), okrąg wpisany i opisany na trójkącie
(VIII.10), długość łuku i pole wycinka (VIII.6), wielokąty foremne (IX.1).

- **Вердикт:** С. Параметризуется, но нужно жёстко контролировать «красивость» углов (кратные 5°
  или 10°, а лучше — из конечного набора 30/45/60/90/120/135/150) и радиусов, иначе длина дуги/
  площадь сектора будут содержать некрасивые иррациональные множители π при «неровных» градусах
  (что математически корректно, но не похоже на задачу из sprawdzianu).
- **Оценка шаблонов:** 10–14. Связь вписанного и центрального угла на одной дуге (2 формы: найти
  центральный по вписанному и наоборот), радиус вписанной/описанной окружности треугольника
  (2–3, отдельно — частный красивый случай прямоугольного треугольника: R = c/2), длина дуги (1–2),
  площадь сектора (1–2), свойства правильного многоугольника — периметр, апофема, внутренний угол
  (2–3).
- **Типичные параметры:** угол в градусах (кратен 5° или 10°, диапазон 10–350° для центрального),
  радиус (целое 2–20), стороны треугольника (часто — пифагоровы тройки для «красивого» случая
  прямоугольного треугольника). Реалистично **~10–20 комбинаций/шаблон** — пул «красивых» углов и
  радиусов заметно у́же, чем в чистой арифметике.
- **Разброс сложности:** 1–3, теоремы о вписанном угле обычно тяготеют к уровню 2–3.
- **Непараметризуемое:** формально нет отдельной нешаблонизируемой подтемы, но многие реальные
  задачи опираются на чертёж окружности с отмеченными углами/хордами — если тренажёр текстовый,
  формулировки придётся тщательно описывать словами (см. риск рендеринга диаграмм).

### `lo2.trigTriangles` — Trygonometria w trójkątach (расширение `lo2.trigAcute`)
Подтемы по чеклисту: funkcje trygonometryczne kątów 0°–180° (VII.1), pole trójkąta P=½ab·sinγ,
twierdzenie cosinusów (VII.3), pola czworokątów z trygonometrią (VIII.12).

- **Вердикт:** Л/С. Вычисление значения тригонометрической функции для «специального» угла и
  применение формул площади/теоремы косинусов — параметризуется хорошо, но **угол здесь — не
  непрерывный диапазон, а параметр-перечисление** (0°, 30°, 45°, 60°, 90°, 120°, 135°, 150°, 180° —
  единственные углы, для которых на уровне P ожидается точное значение без калькулятора). Это
  важный нюанс для дизайна `params`: нужен тип «choice» из фиксированного списка, а не `intRange`.
- **Оценка шаблонов:** 8–12. Значение функции при специальном угле (1, по сути перечисление),
  проверка тождества sin²+cos²=1 (1), площадь треугольника через ½ab·sin γ (1–2), теорема
  косинусов — найти сторону / найти угол (2–3), площадь параллелограмма/ромба через
  тригонометрию (1–2), решение прямоугольного треугольника базовыми отношениями (1–2).
- **Типичные параметры:** стороны треугольника — целые 2–30; угол — «choice» из ~9 специальных
  значений. Реалистично **~10–20 «естественных» комбинаций/шаблон** — при 9 углах и умеренном
  числе пар сторон многие комбинации дают некрасивый (иррациональный без упрощения) результат по
  теореме косинусов, поэтому реальный полезный пул меньше формального произведения.
- **Разброс сложности:** 1–3, теорема косинусов и площадь через синус обычно 2–3.
- **Непараметризуемое:** нет.

## Итоги (грубая оценка для планирования, не обещание)

- **SP5 (9 тем):** шаблонов **≈ 100–135** (сумма диапазонов по темам); плюс **≈ 15–22** ручных
  задач (полигоны + сетки многогранников). При среднем **~15–25 комбинаций/шаблон** (у чистой
  арифметики выше, у геометрии/word problems ниже) — оценочно **≈ 1500–3300 готовых задач** на
  языке (без учёта того, что каждый язык считается отдельно, если нужен раздельный подсчёт по
  RU/EN/PL — количество *шаблонов* и *комбинаций* от языка не зависит, меняется только объём
  текста).
- **LO2-P (6 тем):** шаблонов **≈ 50–75**; плюс **≈ 8–12** ручных задач (в основном «читать график
  параболы», если не будет механизма рисования). При среднем **~12–20 комбинаций/шаблон** (ниже,
  чем у SP5 — больше ограничений типа дискриминанта и «специальных» углов) — оценочно **≈
  600–1500 готовых задач**.
- **Итого SP5 + LO2-P:** **≈ 150–210 шаблонов**, **≈ 25–35 ручных задач**, **≈ 2100–4800 готовых
  задач** после рендера — грубая оценка порядка величины для планирования пилота, не финальная
  цифра.

## Сквозные риски (влияют на все темы)

1. **Согласование числительных RU/PL.** Затрагивает в первую очередь word problems со счётными
   существительными (яблоки, рабочие, дни, ученики) — это примерно `sp5.natural` (сюжетные
   задачи), `sp5.fractions`/`sp5.decimals` (доля от количества предметов), `sp5.integers`
   (температура — не считово, риска нет), `lo2.rational` (обратная пропорциональность:
   «работники», «дни») и частично `lo2.quadratic`/`lo2.quadEq` (оптимизационные word problems).
   Чисто вычислительные темы (`sp5.divisibility`, `sp5.area`, `sp5.cuboids`, `lo2.polynomials`,
   бо́льшая часть `lo2.quadEq`) этого риска почти не несут — там либо нет счётных существительных,
   либо они фиксированы («сторона», «площадь»). Оценочно **~25–35% шаблонов** в этом наборе тем
   реально требуют аккуратной работы с числом/падежом. План уже закладывает решение —
   `Intl.PluralRules` плюс объект `{one, few, many, other}` на каждое склоняемое существительное в
   шаблоне; это снимает риск на уровне механизма, но не снимает **трудозатраты на авторство**:
   на каждое склоняемое существительное в каждом шаблоне нужно вручную написать 3–4 формы текста
   на RU и проверить формы на PL (у польского и русского разные правила множественного числа —
   `Intl.PluralRules('pl')` и `Intl.PluralRules('ru')` дают разные категории для одних и тех же
   чисел, это не «один текст на оба языка»).

2. **Удержание «красивых» чисел под `constraint`.** Для чистой арифметики (сложение, площадь
   прямоугольника, разложение на множители) почти любой случайный набор параметров даёт приемлемый
   результат — отбраковка минимальна. Для алгебры с дискриминантом (`lo2.quadratic`, `lo2.quadEq`)
   и для геометрии с углами/радиусами (`sp5.angles`, `lo2.circles`, `lo2.trigTriangles`) валидный
   пул при случайном переборе может быть в несколько раз меньше, чем произведение размеров
   диапазонов параметров — там правильнее не перебирать params «вслепую», а генерировать их через
   `derive` в обратную сторону (сначала выбрать «красивый» ответ, потом вычислить параметры). Это
   не блокер, но ощутимо увеличивает сложность авторства именно для таких тем по сравнению с
   арифметикой.

3. **Проверка (`verify`) сложнее для алгебры/геометрии, чем для арифметики.** Нынешний
   `verifyTask.ts`/`verifyExpression`-подход — по сути численная перепроверка одного числа или
   выражения. Для арифметики и площадей это прямое сравнение чисел. Для `lo2.polynomials`
   (упростить/разложить многочлен) корректный ответ — это класс эквивалентных записей, и
   численного сравнения недостаточно без раскрытия/приведения через mathjs (`simplify`/`expand`) —
   нужно либо сравнивать на нескольких случайных значениях переменной (эквивалентно с точностью до
   ошибки), либо честно символьно. Для геометрии с углами/секторами (`lo2.circles`) ответы часто
   содержат π или квадратные корни — нужно решить единый формат ответа (точная форма `kπ` vs.
   десятичное приближение) и заложить допуск на сравнение с плавающей точкой, причём одинаково на
   всех трёх языках. Это самая техническая часть риска и, скорее всего, отдельная небольшая задача
   при проектировании `TaskTemplate`/рендерера, а не что-то решаемое «по ходу».

4. **Зависимость от рендеринга диаграмм.** Заметная часть тем — почти вся геометрия — в реальных
   sprawdzianach опирается на чертёж (`sp5.angles`, `sp5.polygons` — оси симметрии, `sp5.cuboids` —
   сетки, `lo2.quadratic` — чтение графика параболы, `lo2.circles` — окружность с отмеченными
   углами/хордами). Если у тренажёра сейчас нет механизма рисовать/показывать геометрическую
   картинку по параметрам шаблона, это ограничивает такие подтемы либо чисто словесными
   формулировками (менее естественными, чем «настоящая» школьная задача), либо переводит их в
   ручной набор с заранее подготовленными изображениями. Это влияет на 4–5 тем из 15 и стоит
   решить на уровне архитектуры **до**, а не после того, как будут написаны первые геометрические
   шаблоны — иначе часть авторской работы придётся переделывать.

## Рекомендация: с чего начать прототип `TaskTemplate`

Для обкатки инструментов (рендерер, `constraint`/`derive`, verify, `Intl.PluralRules`) лучше
сначала не трогать темы с зависимостью от диаграмм — их стоит отложить до решения по рендерингу
геометрии. Предлагаемые 5 тем для пилота, покрывающие и «чистые вычисления», и word problems, и
более сложную символьную/геометрическую проверку:

1. **`sp5.natural`** — самая дешёвая точка входа: чистая арифметика (быстрый тест механизма
   `params`/`constraint`) плюс пара word problems (тест `Intl.PluralRules` на реальном, но не
   самом сложном материале).
2. **`sp5.divisibility`** — чистая теория чисел без геометрии и почти без word problems; хороший
   тест `constraint` между двумя параметрами (НОД/НОК) без риска «некрасивых» чисел.
3. **`sp5.decimals`** или **`sp5.fractions`** — тест `constraint`, специфичного для куррикулума
   (лимит «≤6 значащих цифр» 2024 г.), и умеренный объём word problems для теста согласования
   числительных на новом типе существительных (деньги, единицы измерения).
4. **`lo2.quadEq`** — первый алгебраический (не арифметический) шаблон: тест `derive`
   «от желаемых корней — к коэффициентам», чтобы обкатать подход «генерировать в обратную
   сторону» для избежания некрасивых чисел; здесь же — естественная лестница сложности Δ>0/=0/<0.
5. **`lo2.polynomials`** — специально ради того, чтобы обкатать **символьную** проверку
   (`verify` через раскрытие/приведение многочлена), а не только численную — это единственный
   технически новый тип проверки среди простых кандидатов, и лучше столкнуться с ним на пилоте,
   чем на 150-й теме.

Геометрические темы (`sp5.angles`, `sp5.polygons`, `sp5.cuboids`, `lo2.quadratic`, `lo2.circles`,
`lo2.trigTriangles`) разумно взять во вторую волну — после того как решится вопрос с рендерингом
диаграмм и появится референс по авторству ручных наборов (полигоны, сетки многогранников).
